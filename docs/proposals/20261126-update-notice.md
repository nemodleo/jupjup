# 제안 — 새 버전 알림 (2026-11-26, 승인 전)

캔버스 보드 「16 · 제안 — 새 버전 알림」(project/Proposal-UpdateNotice.dc.html)의 5·6·7·8번과 같은 글. 커밋하지 않음.

## 디자인 무브
① 배너는 버전마다 한 번, 줄은 받을 때까지. 시스템 알림은 새 버전 하나에 한 번만(updateNotified에 적어 둠), 메뉴 맨 위 새 버전 줄은 받을 때까지 남는다. 왜: 배너는 순간 알림이라 놓쳐도 되게 하고, 받을 곳은 계속 보이는 줄이 맡는다. 같은 버전을 다시 띄우면 조르기다.
② 끄는 곳은 하나. 메뉴 「새 버전 확인」 하나. 끄면 확인도 배너도 없다. 배너만 끄려면 macOS 시스템 설정 › 알림 › 줍줍. 왜: 버린 안(토글 둘)은 「앱」 칸을 한 줄 늘리는데, 배너만 끄는 일은 macOS 설정이 이미 한다.
③ 권한은 처음 알릴 때 묻는다. 첫 실행이나 설정에서 미리 묻지 않고, 새 버전이 실제로 나온 순간 한 번. 거절해도 메뉴 줄은 그대로 뜬다. 왜: 첫 실행 안내 창은 화면 기록 권한 하나만 챙기게 두고(7번 보드), 알림 권한은 쓸 일이 생긴 때 물어야 왜 묻는지 보인다.
④ 누르면 바로 받는 곳으로. 배너를 누르면 메뉴 줄 「내려받기」와 같은 동작 — 내려받기 주소를 기본 브라우저로(지금의 주소 검사 그대로: jupjup.d-t-it.com/download/ · GitHub 릴리스만). macOS가 낮아 못 쓰는 버전이면 시스템 설정 「소프트웨어 업데이트」. 왜: 누른 뒤 메뉴를 다시 열어 찾게 하면 한 단계가 는다.
⑤ 하던 일을 끊지 않을 때만. 고르기 화면(캡처 오버레이)이 떠 있거나 「줍는 중」·결과 토스트가 떠 있는 동안에는 배너를 미룬다. 1초마다 보다가, 하던 일이 끝나고(고르기 화면이 닫히고 토스트가 사라지고) 5초쯤 지나 띄운다. 소리 없음, 배지 없음. 왜: 줍줍 토스트도 화면 오른쪽 위라 배너와 겹치고, 고르는 중에 뜬 배너는 고를 자리를 가린다.
⑥ macOS가 낮으면 사실만. 피드의 min_os보다 낮은 맥에서는 「줍줍 2.0 버전은 macOS 26부터예요」 · 「macOS를 올리면 쓸 수 있어요.」 배너와, 내려받기 대신 「macOS 26부터」가 붙은 메뉴 줄. 눌러도 DMG를 받지 않는다. 왜: 열리지 않는 DMG를 받게 하면 설치 단계에서 실패를 겪는다. 제목에서 버전 숫자 뒤에 조사를 붙이지 않는다(「… 버전은」).

## 검산
- 배너 글자 칸(추정) — macOS 배너 폭 ≈344pt − 여백 14·14 − 아이콘 32 − 간격 10 = 본문 줄 ≈274pt, 제목 줄은 시각 「지금」(≈30pt)을 빼고 ≈240pt. 제목 13pt 굵게 한 줄(넘으면 끝이 「…」), 본문 13pt 배너에서 2줄까지로 잡음.
- 제목 · 보통 — 「줍줍 1.4 버전이 나왔어요」 15자(한글 9자 × 13 + 「1.4」 19 + 띄어쓰기 3 × 3.6) ≈ 147pt < 240. 가장 긴 버전 「10.12.3」이면 +30 → ≈177pt < 240. 영어 「Jupjup 1.4 is available」 23자 ≈ 150pt.
- 제목 · macOS 낮음 — 「줍줍 2.0 버전은 macOS 26부터예요」 23자: 한글 9자 × 13 = 117 + 「2.0」 19 + macOS 44 + 「26」 15 + 띄어쓰기 4 × 3.6 = 14 → ≈209pt < 240. 버전이 「10.12.3」이면 ≈239pt로 한계에 닿지만 줍줍은 x.y 꼴만 쓴다. 영어 「Jupjup 2.0 needs macOS 26 or later」 34자 ≈ 216pt < 240.
- 가장 긴 언어 — 독일어·러시아어 제목은 영어보다 30~45% 길어질 수 있다. 라틴 굵게 13pt 평균 ≈6.4pt/자(영어 낮음 제목 216pt ÷ 34자) → 제목 37자 이하(키릴 33자)면 한 줄. 넘는 언어는 개발 때 번역하며 줄여 쓴다. 한국어·영어만 이 보드에, 나머지 33개는 개발 때 번역, 없는 키는 영어로 떨어짐(지금 구조).
- 본문 — 「누르면 내려받아요. 메뉴 맨 위 줄에서도 받을 수 있어요.」 31자 ≈ 320pt → 2줄(≤548). 영어 52자 ≈ 345pt → 2줄. 낮음 「macOS를 올리면 쓸 수 있어요.」 ≈ 172pt → 1줄, 영어 「Update macOS to use it.」 ≈ 145pt → 1줄.
- 메뉴 줄(main.swift 486행 계산) — 너비 = 「새 버전 2.0」(12.5 굵게 ≈62) + 「macOS 26부터」(11.5 ≈78) + 6 + 12 + 30 = ≈188, +12 = ≈200 → 메뉴 폭 max(220, …) = 220 그대로. 영어 「New version 2.0」 ≈93 + 「macOS 26+」 ≈60 + 48 + 12 = ≈213 → 236 그대로. 상한 320에서 뒤쪽 글자에 남는 자리: 러시아어 「Новая версия 2.0」 ≈115 기준 ≈145pt(라틴 24자).
- 가장 작은 글자 — 목업 안 10px(갈래 제목·키 모양, 지금과 같음). 새로 생기는 글자 중 가장 작은 것은 배너 시각 11px, 메뉴 「macOS 26부터」 11.5px. 보드 설명 13px.

## 요소 확인
- 알리기: 시스템 알림(새 버전마다 한 번, 소리·배지 없음) + 메뉴 맨 위 새 버전 줄(그대로, 받을 때까지). 토스트는 안 씀 — 줍기 결과 전용
- 기다리기: 없음 — 확인은 뒤에서 GET 하나(10초 제한), 보이는 기다림을 두면 지어낸 기다림
- 어디쯤인지 보이기: 없음 — 단계가 하나뿐인 알림
- 빈 화면: 없음 — 새 버전이 없으면 줄·배너가 없는 것이 정상. 권한 거절은 빈 화면 대신 메뉴 줄만(③)
- 입력: 그대로 — 토글 「새 버전 확인」 하나(②)
- 누르는 것의 상태: 메뉴 새 버전 줄(macOS 낮음) 기본·호버·눌림은 지금 줄과 같은 규칙, 비활성 없음. 배너의 상태는 macOS가 그림
- 이동과 전환: 배너 누름 → 기본 브라우저의 내려받기 주소, macOS 낮음이면 시스템 설정 「소프트웨어 업데이트」(④⑥). 앱 안 화면 이동 없음
- 움직임: 없음 — 배너 등장·사라짐은 macOS가 함, 메뉴 줄은 지금처럼 움직임 없이 나타남
- 손짓: 없음 — 배너를 밀어 넘기는 것은 macOS 손짓이고, 그냥 두어도 사라져 같은 결과
- 끝내기: 없음 — 받으면 줄이 조용히 사라짐, 일이 작아 축하 없음
- 배치: 그대로 — 새 버전 줄 자리(「글자 줍기」 줄 바로 아래)와 메뉴 폭 220 그대로
- 첫 실행: 권한 요청(permission prompt)을 첫 실행이 아니라 처음 알릴 때로(③). 첫 실행 안내 창(7번 보드)은 그대로
- 내보내기와 공유: 없음 — 공유할 것이 없음
- 대화 화면: 없음 — 대화 기능이 없음
- 하지 않는 것: 조르기 없음 — 한 버전에 배너 한 번(①), 거절 뒤 다시 안 물음(③), 소리·배지 없음(⑤), 자동 설치 없음
- 보이는 결: 그대로 — 메뉴 줄은 먹·한지·주홍 그대로, 배너는 macOS 모양이라 우리 색을 안 씀
